Gate 1 — capability RBAC (per report type)

Existing RBAC is coarse: require_roles("findings") grants the whole findings surface. For AI that is too blunt — a dbsec role holding findings must not request an executive briefing. New additive namespace; ROLES_HIERARCHY is not modified.

Gate 2 — tenancy: ReportScope, a frozen value object

The structural fix. Created once per request, immutable, and a required positional parameter of every data accessor — so a function that reads the warehouse cannot be called without a scope.

from dataclasses import dataclass from typing import FrozenSet @dataclass(frozen=True, slots=True) class ReportScope: """Immutable, fully-resolved tenant scope. Created once, passed explicitly. No `claims` accessor and no `get_current_user()` call lives in this object: the scope is resolved once and cannot drift mid-request. """ subject: str roles: FrozenSet[str] department_ids: FrozenSet[str] # already province-expanded branch_ids: FrozenSet[str] province_ids: FrozenSet[str] nationwide: bool scope_class: ScopeClass scope_hash: str # sha256 of the canonical scope tuple def tenant_filter(self, model): # delegates to app.api.auth.tenant_filter ... def permits_department(self, dept_id: str) -> bool: ... def permits_branch(self, branch_id: str) -> bool: ...

Accessors require scope positionally

SAFE — scope is mandatory
async def findings_severity_counts(scope: ReportScope, db): ...
NEVER WRITTEN
# no scope parameter exists — cannot be called safely async def findings_severity_counts(db): ...
Test S6 enforces this mechanically by signature inspection across the module — the convention fails the build rather than relying on code review. See Verification suites.

Scope classes — making the compliance gap explicit

class ScopeClass(str, Enum): TENANT_SCOPED = "tenant_scoped" # filtered by ReportScope.tenant_filter() ESTATE_WIDE = "estate_wide" # structurally unscopable today — MUST be disclosed

Every fact carries one. Estate-wide facts must propagate to the response envelope and be attributed as estate-wide in the narrative — enforced by the verifier, not by prompt politeness.

Provable scope non-widening

  • ReportScope is frozen and has no mutator.
  • Accessors never widen — tenant_filter() is applied, never composed away.
  • A nationwide role gets tenant_filter() -> None (existing behaviour). The AI layer preserves this exactly and never re-derives it.
  • A department-scoped role with empty scope gets expression.false() — the existing fail-closed path — and renders empty with an explicit notice, never estate-wide.

03 Claim permission — RBAC inside the output

A role may be permitted to request a report but not to see everything inside it. This layer applies to the generated text, not the request. Click a claim class to see who holds it.

Claim classWhat it lets the narrative nameHeld by
Enforcement. After generation the verifier scans for claim patterns (CVE-\d{4}-\d+, alert UUIDs, department names, rule ids, owner names) and discards any sentence containing a class the role does not hold. A failed verification returns the deterministic template, never the model text.

exec sees

"Estate risk is 62, critical exposure concentrated in 4 applications" — no CVE list, no owner names.

soc sees

"CVE-2026-31429 on payment-gateway, alert a1b2…, owner Payment Ops".

Today the platform differentiates only by which dashboard you land on. This differentiates by what your narrative is permitted to say.

Deterministic fallback

When it engages

Model unavailable · breaker open · verification failed · llm_enabled=false.

What renders

A static Jinja2 template driven by the same fact pack — same numbers, no prose flourish. fallback_used:true is returned.

Because the fact pack is identical in both paths, a fallback report never shows different numbers from an AI report for the same scope and moment. This also makes the whole capability safely demoable and testable with no GPU at all.
