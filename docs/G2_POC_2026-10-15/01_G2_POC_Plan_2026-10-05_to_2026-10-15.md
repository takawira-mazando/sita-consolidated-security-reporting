## 2. What we are building, in one paragraph

An **AI report agent** that generates a written security report by prompting a self-hosted language model, where **the prompt itself is assembled from the caller's RBAC claims and their frozen tenancy scope**. The agent retrieves only in-scope rows, tags every fact as tenant-scoped or estate-wide, injects only the claim classes the caller's role is permitted into the prompt, then verifies the model's output against the fact pack before returning it. A deterministic fallback serves the same numbers if the model is unavailable.

**This replaces the G2 frontend viewer page (activity 17.5).** Reports are no longer another React dashboard; they are generated per request by a role-aware agent. The existing Vite frontend is not modified.

## 5. The pipeline

```
POST /api/v1/reports-ai/generate        JWT → claims
        │
        ├─ GATE 1 · RBAC         require_report_permission("executive_briefing")
        │                        permission = report_ai:<report_type>
        │                        default-deny — absent role gets NOTHING
        │
        ├─ GATE 2 · TENANCY      resolve_report_scope(claims) → ReportScope (frozen)
        │                        scope_hash = sha256(canonical scope tuple)
        │
        ├─ RETRIEVAL             accessors take scope as FIRST POSITIONAL arg
        │                        tenant_filter(claims, model) — delegated, never re-implemented
        │                        empty scope → expression.false() → fail closed
        │
        ├─ DISCLOSURE            every fact tagged TENANT_SCOPED | ESTATE_WIDE
        │                        estate-wide must be declared — verifier enforces
        │
        ├─ FACT PACK             pure builder + fact_pack_hash
        │                        identical pack feeds BOTH the model and the fallback
        │
        ├─ PROMPT  ◄── THE POINT  allowed_claim_classes injected FROM THE CALLER'S ROLE
        │                        scope stated in the prompt for attribution only
        │                        temperature 0.2, constrained narrative_html
        │                        model receives facts only — no DB, no SQL, no tools
        │
        ├─ GENERATE              Ollama /v1/chat/completions via httpx + CircuitBreaker
        │
        └─ VERIFY                ① every numeral in prose exists in the fact pack
                                 ② claim filter — DISCARD sentences holding unheld classes
                                 ③ scope_hash match across envelope + cache + audit
                                 any failure → deterministic template, never model text
```

### 5.1 Why the prompt is not the control

The prompt *states* the restriction. The verifier *enforces* it, independently. The adversarial suite attacks this directly: attempts to name another province, to widen scope, or to leak a CVE id must all fail at the verifier even when the prompt permitted them.

**Independence, restated for the current team.** The verifier is written by **Peter Rashaya**; the prompt builder and templates it polices are **Takawira's**. That separation is why two developers are on this window at all.

One of the three original control claims **does not hold** under this ownership and must not be repeated in front of the client:

| Claim | Status |
|---|---|
| **1. The verifier is not written by the prompt author.** | **HOLDS.** Verifier (Peter) vs prompt builder and templates (Takawira). |
| **2. Ground truth is not authored by the model author.** | **DOES NOT HOLD** in the structural sense originally claimed. Takawira owns the scope, capability, accessor and context layer **and** the prompt builder. **Restated:** scope and capability *delegate* to `tenant_filter()` and SQL introspection, neither of which can be widened from a prompt; the prompt builder only serialises facts the fact pack already contains (`pack.serialise(allowed=claims)`); and the live containment proof is run by Peter, not by the author of the prompt. |
| **3. The structural filter cannot be bypassed by prompt text.** | **HOLDS.** `pack.serialise()` is a code boundary, not an instruction in prose. |

## 6. Role-aware prompting — the core of the request

`ClaimClass` describes what a role may see **named** in the output. This is a second RBAC layer applied to the *text*, not the request.

| ClaimClass | exec | compliance | soc | appsec | dbsec |
|---|:---:|:---:|:---:|:---:|:---:|
| `headline_metrics` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `risk_buckets` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `app_names` | ✓ | — | ✓ | ✓ | ✓ |
| `department_names` | ✓ | ✓ | ✓ | — | — |
| `aggregate_compliance` | ✓ | ✓ | — | — | — |
| `cve_ids` | — | — | ✓ | ✓ | — |
| `alert_ids` | — | — | ✓ | — | — |
| `owner_names` | — | — | ✓ | — | — |
| `rule_ids` | — | — | ✓ | — | — |

The prompt template is assembled per role:

```yaml
report_type: executive_briefing
version: 1
model_tier: small
system: |
  You are a briefing writer for the South African national security estate.
  Write ONLY from the FACTS block. If a figure is absent write
  "not tracked in this build" — never estimate.
  Do not name any entity absent from ALLOWED CLAIM CLASSES.
input:
  facts_from: context.build_executive_context     # pure, scope-bound
  max_tokens: 900
  temperature: 0.2
constraints:
  - figures_only_from_facts: true
  allowed_claim_classes: [headline_metrics, risk_buckets, app_names,
                         department_names, aggregate_compliance]   # ← INJECTED FROM ROLE
  - estate_wide_attribution: required
output:
  schema: narrative_html
```

**Same report type, same fact pack, two roles, materially different text.** That contrast is demo item 5.
